# Resume Workflow

## Intake

Collect only what is needed for the target resume. Start with the user's goal, then ask for missing material in small batches.

Useful prompts:

- 目标岗位是什么？更偏前端、全栈、产品型技术、管理，还是某个行业方向？
- 这份简历主要投递给谁看：HR、技术面试官、熟人内推、外包/项目制客户？
- 哪些项目最能代表你？每个项目的业务目标、技术栈、你负责的部分、难点和结果是什么？
- 有没有必须保留或必须弱化的信息？

## Content Strategy

Choose a resume angle before writing:

- Delivery-oriented: emphasize project landing, multi-terminal development, cross-team coordination, production troubleshooting.
- Technical depth: emphasize architecture migration, component abstraction, performance, real-time communication, maps, desktop integration, engineering quality.
- Product-aware: emphasize requirement decomposition, business flow design, user scenarios, configuration systems, operational loops.
- Growth-oriented: emphasize AI-assisted development, backend/database learning, full-stack collaboration, ownership expansion.

## Recommended Section Order

For a Chinese frontend engineer resume:

1. Name, target role, contact
2. Profile summary
3. Core skills
4. Work experience
5. Featured projects
6. Other projects
7. Education/certifications
8. Self-improvement or AI tooling, only if it supports the target role

Move featured projects above work experience only when the project portfolio is stronger than company history or the user is changing tracks.

## Bullet Transformation

Convert raw notes into focused bullets:

Raw: “做了后台页面和接口联调。”

Better: “基于 Vue3 + Element Plus 完成订单、商品与权限配置模块开发，对接后端接口并处理表单校验、状态流转和列表筛选等核心交互。”

Raw: “负责小程序支付。”

Better: “对接微信支付链路，完成下单、支付唤起、支付结果同步和订单状态更新，支撑商城购买闭环。”

Raw: “项目从 Vue2 升级到 Vue3。”

Better: “主导系统从 Vue2 迁移到 Vue3，梳理页面结构、状态管理和地图能力调用方式，降低后续功能维护成本。”

## Artifact Flow

Prefer this sequence:

1. Produce a Markdown/content draft for quick review.
2. Create a clean primary resume artifact.
3. Generate optional visual variants only after content is stable.
4. Export final DOCX/PDF and keep source files editable.
5. Summarize decisions and remaining risks.

## Final Review Checklist

- Target role is obvious in the first screen/page.
- Summary matches the strongest evidence in the project section.
- Dates and company/project names are consistent.
- Skills listed are supported by work/project content.
- Featured projects show ownership, not only participation.
- No invented metrics, fake seniority, or unverifiable claims.
- Contact info is present only in final private deliverables, not in reusable examples.
- PDF print layout has no text clipping, overlapping, or awkward orphan lines.
